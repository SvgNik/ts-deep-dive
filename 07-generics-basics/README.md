# 07 · Generics Basics

## Что изучено

- Проблема: тип результата фиксируется в точке определения, знание о конкретном типе появляется в точке вызова
- Почему не решают: дублирование функций, `any`, union в сигнатуре
- Type parameter как переменная для типа, связывается заново на каждом вызове
- Type argument inference: кандидат берётся из аргумента по позиции `T`
- Три случая явного типового аргумента: нет кандидатов, кандидат точнее нужного, конфликт кандидатов
- Несколько type parameters, число = число независимых типов
- Generic type aliases и generic interfaces, TS2314
- Дефолтные типовые параметры, TS2706
- Generic классы на уровне знакомства
- Naming: `T`, `A`/`B`, `K`/`V`, осмысленные имена при трёх и более
- Правило двух вхождений, декоративные generics, `T` только в return position, generic вместо union

## Что должен уметь

- Объяснить, что связывает каждый типовой параметр в сигнатуре
- Написать generic-функцию, сохраняющую связь вход-выход
- Определить, где inference сработает, а где нужен явный типовой аргумент
- Отличить рабочий generic от декоративного
- Понимать, почему `parseJson<T>` это замаскированный `as`

## Сложные моменты

- `Array(count)` возвращает `any[]` — скрытый `any`, компилятор молчит
- Проверка `arr.length > 0` не снимает `| undefined`: тип `T[]` не несёт длины
- Union из одного аргумента выводится, из нескольких — TS2345
- Пустой литерал даёт `T = never`, отсутствие кандидата — `T = unknown`
- `(x) => { x.value; }` возвращает `void`, `B` выводится как `void`
