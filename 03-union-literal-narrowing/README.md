# 03 · Union, Literal Types, Narrowing

## Что изучено

- Union types: синтаксис `|`, множество значений vs множество операций
- Literal types: тип из одного значения, union of literals вместо магических строк
- Widening: причина - изменяемость значения, не ключевое слово `const`
- Три способа сохранить literal type: `const`, `as const`, явная аннотация
- Narrowing как механизм: type guard - обычный JS-код, TS извлекает из него знание
- `typeof` - для примитивов
- Truthiness - для отсечения falsy, включая `null` и `undefined`
- `===` - для literal types и явного сравнения с `null` / `undefined`
- `in` - для объектных union с разными полями
- `instanceof` - для экземпляров классов (`Date`, `Error`)
- Control flow analysis: тип сужается накопительно по ветвлениям
- Порядок guard: широкий guard съедает узкий, если стоит раньше
- `unknown` как предельный union (формально - TS 11)
- Попутно: `new Date(timestamp)`, `toISOString()`

## Что я должен уметь

- Читать union и определять, какие операции разрешены без проверки
- Выбирать guard по признаку различия членов union, а не по памяти
- Объяснять причину widening, а не называть ярлык
- Ставить guard в правильном порядке и объяснять, почему порядок такой
- Выбирать между truthiness и явным сравнением по смыслу данных
- Считать количество ветвей до написания кода: сколько разных `return`
- Понимать, где narrowing не защищает, и снимать значение в локальную `const`

## Сложные моменты

**TS следит за присваиваниями, а не за вызовами.** Narrowing свойства объекта
выживает после вызова функции: `npm run check` проходит чисто, а runtime падает
с `TypeError`. Это осознанная неточность дизайна TypeScript - иначе narrowing
слетал бы после каждой строки с вызовом. Правило "сузил - вытащи в локальную
`const`" остаётся, но защищает от runtime, а не от компилятора. Найдено при
проверке кода в редакторе: объяснение ментора не сошлось с поведением TS.

**Тип параметра и return type - независимые контракты.** Параметр
`"guest" | "user" | "admin"` не обязывает возвращать что-то из этого набора.
Именно эта связка блокировала первую задачу.

**Union и widening - разные механизмы.** Union: значения шире, операции уже.
Widening: выведенный literal расширяется до базового типа из-за изменяемости.
Оба про "расширение", путаются легко.

**Порядок guard.** Не "от общего к частному", а наоборот: который захватывает
больше значений - тот ниже. Иначе широкий guard делает узкую ветвь мёртвой.
