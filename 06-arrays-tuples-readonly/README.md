# 06 · Arrays, Tuples, Readonly

## Что изучено

- `T[]` и `Array<T>` эквивалентны; приоритет скобок: `(string | number)[]` против `string | number[]`.
- Inference по массиву собирает union типов элементов и применяет widening, потому что содержимое изменяемо.
- Пустой массив без аннотации - evolving array, не `any[]`.
- Тип `T[]` не несёт информации о длине, поэтому без флага компилятор оптимистично отдаёт `T` на любой индекс.
- `noUncheckedIndexedAccess` добавляет `| undefined` к индексному доступу; `!` это ложь компилятору, не решение.
- Итерация (`for...of`, `map`, `filter`, `forEach`) флагом не затронута - элемент отдаётся напрямую.
- Tuple - массив с фиксированной длиной и типом на каждой позиции; несовпадение даёт TS2322 с указанием количества элементов.
- Индексный доступ к tuple честен: длина известна, `| undefined` не добавляется; выход за границу - TS2493.
- Мутирующие методы на tuple не заблокированы: `tup.push()` компилируется.
- Именованные элементы `[x: number, y: number]` - документация для подсказок редактора.
- Опциональные элементы только в хвосте; rest в tuple задаёт минимальную структуру: `[Task, ...Task[]]`.
- Tuple по литералу не выводится: нужна явная аннотация или `as const`.
- `readonly T[]` и `ReadonlyArray<T>` эквивалентны; мутирующих методов в типе физически нет (TS2339), запись по индексу - TS2542.
- Совместимость односторонняя: `T[]` → `readonly T[]` можно, обратно TS4104.
- `readonly` поверхностный: защищает структуру массива, поля объектов внутри изменяемы.
- `readonly` не снимает `noUncheckedIndexedAccess`; `| undefined` убирает только tuple.
- `as const` на массиве даёт `readonly [литералы]` - tuple, readonly и literal types разом.

## Что должен уметь

- Выбирать между `T[]` и tuple по тому, значат ли позиции разное.
- Работать с `| undefined` от индексного доступа через narrowing, а не через `!`.
- Объявлять параметры-массивы как `readonly`, когда функция только читает.
- Отличать блокировку от `readonly` (TS2339 на `push` и `sort`) от отсутствия метода из-за `lib` (TS2339 + TS7006 на параметрах callback).
- Возвращать tuple, когда функция отдаёт несколько значений разного смысла.
- Различать случаи, когда пустой вход даёт `undefined`, а когда осмысленный нулевой результат.

## Сложные моменты

- **`readonly` это не флаг, а другой тип.** `push` даёт TS2339 «свойства не существует» - тот же код, что при опечатке в имени метода.
- **TS2339 на `toSorted` может означать не `readonly`, а старый `lib`.** Признак: рядом висят TS7006 на параметрах callback, потому что contextual typing неоткуда взяться.
- **`readonly` поверхностный, spread тоже.** `[...readings]` копирует массив, объекты внутри общие.
- **Ключ из union не то же самое, что индекс массива.** `STATUS_LABELS[status]` не даёт `| undefined`: набор ключей известен. `readings[0]` даёт: длина неизвестна.

## Notes

Коды ошибок темы: TS2322, TS2339, TS2493, TS2532, TS2542, TS4104, TS7006, TS18048.

**Ключевая находка темы.** `tup.push("oops")` на tuple компилируется - восьмое подтверждение правила модуля. Проверка длины работает при присваивании, `push` присваиванием не является. Общая формула трёх случаев M2 (narrowing после вызова в TS 03, `readonly` на свойствах в TS 04, `push` на tuple в TS 06): **компилятор отслеживает присваивания, а не операции.**

**Развилка `undefined` против нулевого результата.** `getTempRange([])` возвращает `undefined` - минимума и максимума пустого множества не существует. `summarize([])` возвращает `[0, 0]` - ноль заказов на сумму ноль это валидный ответ. Граница проходит через то, существует ли осмысленный результат, а не через то, пустой ли вход.
