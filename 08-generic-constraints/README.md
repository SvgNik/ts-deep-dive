# 08 · Generic Constraints

## Что изучено

- Зачем constraints: `T` без ограничения это множество всех типов, операция
  должна быть безопасна для каждого члена, поэтому не разрешена ни одна.
- Синтаксис `T extends X`: X это upper bound, `T` может быть уже, но не шире.
  Проверка происходит в точке вызова (TS2345), а не в теле функции.
- Constraint не заменяет `T`: внутри и на выходе остаётся конкретный тип
  вызова, а не форма ограничения.
- `keyof T` - union литеральных типов ключей. Первый тип, который вычисляется
  из другого типа, а не пишется руками.
- `T[K]` - indexed access type: тип значения под ключом `K`.
- `K extends keyof T` - отдельная переменная типа для ключа, связывается
  конкретным литералом на каждом вызове.
- Несколько ограниченных параметров: `K1`, `K2` связываются независимо,
  один `K` на два ключа был бы утверждением об их равенстве.
- Порядок типовых параметров не важен, constraint может ссылаться вперёд.
- Дефолт совмещается с ограничением и обязан ему удовлетворять.
- Типичные ошибки: избыточное ограничение, `K extends string` вместо
  `K extends keyof T`, ограничение вместо union, ограничение вместо
  валидации данных.

## Что должен уметь

- Отличить оправданный constraint от избыточного: оправдан, когда без него
  операция не существует (`in`, `Object.keys`, индексация через `T[K]`).
- Связать аргументы между собой в сигнатуре: `value: T[K]` типизируется
  через первые два параметра.
- Объяснить, почему `key: keyof T` теряет точность, и посчитать `T[keyof T]`
  руками.
- Обойти невозможность сравнить `T[K]` внутри функции через параметр
  `compare: (a: T[K], b: T[K]) => number`.

## Сложные моменты

- `K extends keyof T` и `T[K]` сначала выглядели как две отдельные
  конструкции. Связка: `K` ограничивает допустимый ключ, `T[K]` достаёт тип
  значения именно этого ключа.
- `extends` в constraint не преобразует тип, он фильтрует допустимые типовые
  аргументы. То же слово, другой механизм, чем `interface extends`.
- `K extends string` против `K extends keyof T`: ограничение обязано
  связывать `K` с `T`, иначе TS2536 и никакой защиты.
- `T[K]` против `T[keyof T]`: один ключ против всех ключей, конкретный тип
  против union всех значений.

## Notes

- `{ ...obj, [key]: value }` компилируется без проверки значения против типа
  поля: вычисляемый ключ в литерале не сверяется с местом, куда ложится.
  Защиту даёт только своя сигнатура. Вариант `copy[key] = value`
  проверяется честно (TS2322). Четырнадцатое подтверждение правила модуля.
- `readonly` в constraint запрещает запись внутри функции, но не требуется
  от вызывающего: `readonly` не участвует в проверке совместимости.
- Tuple в `groupByKey` существует только из-за явного `reduce<[T[K], T[]][]>`.
  Без него литерал выводится как `(T[K] | T[])[]`, аккумулятор как `never[]`,
  падает сам вызов `reduce` с TS2769.
- `Object.keys` возвращает `string[]`, а не `(keyof T)[]`, и это честно:
  в runtime у объекта могут быть ключи, которых нет в типе.
