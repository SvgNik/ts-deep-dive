# 02 · Basic Types and Inference

## Что изучено

- Примитивные типы: `string`, `number`, `boolean`, `null`, `undefined`, `bigint`, `symbol`.
- Type inference: TS выводит тип из значения; аннотация при инициализации избыточна.
- Literal type vs widening: `const` фиксирует значение, `let` расширяет до базового типа.
- Четыре случая обязательной аннотации: параметры функции, объявление без значения,
  пустой контейнер, тип шире или уже выведенного.
- Evolving any / evolving array: `let x;` и `[]` доращиваются по присваиваниям,
  но ломаются при выносе за линейный поток (TS7005).
- Явный return type как контракт функции.
- Объектные типы inline, вложенные объекты, object literal freshness.
- Массивы: `number[]`, массив объектов, union в массиве и приоритет скобок.
- strictNullChecks: `null` и `undefined` как самостоятельные типы.
- Narrowing через `if` и early return; запрет non-null assertion `!`.
- noUncheckedIndexedAccess: доступ по индексу даёт `T | undefined`.
- Типизация ответа API: `response.json()` возвращает `any` — дыра, закрывается в TS 11.

## Что должен уметь

- Читать тип справа налево и называть структуру словами.
- Определять, где аннотация обязательна, а где дублирует вывод TS.
- Записывать тип параметра и return type, не путая вход с выходом.
- Описывать объектные типы, включая вложенные.
- Доказывать компилятору, что значение есть, вместо заглушения через `!`.
- Типизировать `map` со сменой формы данных и `reduce` с объектом-аккумулятором.
- Типизировать async-функцию через `Promise<T>`.

## Сложные моменты

- Вход и выход функции: тип параметра — то, что приходит снаружи; return type — что уходит наружу.
  Путал четыре раза. Приём: перед сигнатурой проговорить «я передам сюда X, получу отсюда Y».
- Аккумулятор `reduce` не обязан быть числом — это может быть объект или накопительная структура.
  Под strict его тип нужно объявлять явно (index signature).
- Цепочка доступа: параметр колбэка — это один элемент массива, а не весь массив.
- Компилятор замолчал ≠ код правильный: `console.error(Error)` убрал ошибку, но не решил задачу.

## Notes

- Тип пользователя/заказа продублирован в файлах по 4–5 раз — это мотивация к type alias (TS 03/04).
- Разделение слоёв: api-слой бросает через `throw`, вызывающий код ловит через `try/catch`.
  Пустой массив — валидные данные, ошибка запроса — сбой; смешивать нельзя.
- Ошибки должны нести контекст: `throw new Error(\`Request failed with status ${response.status}\`)`.
